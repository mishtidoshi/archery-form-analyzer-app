# Archers

Per-archer profiles. Each archer gets their own directory under `archers/`, created
either through the mobile app's sign-up flow or by hand.

## Structure

```
archers/
├── README.md                 ← this file
└── <archer_id>/               ← one directory per archer
    ├── profile.json           ← canonical archer info: identity, anthropometrics,
    │                             equipment, coaches, study setup, audio config,
    │                             feedback preferences, active coaching focus
    ├── auth.json               ← gitignored: salted password hash, never profile data
    ├── coach_voice.md          ← optional: curated coach cues/tone for the LLM synthesis stage
    ├── coaching_log.md         ← optional: chronological log of coaching sessions
    ├── tournament_observations.md  ← optional: per-tournament notes and patterns
    ├── red_camp_notes.md       ← optional: training-intensive / camp notes
    └── baseline_profile.json   ← generated by tools/calibrate_archer.py once enough
                                    sessions exist
```

None of the optional files are required for the pipeline to work — an archer with
just `profile.json` (created automatically on sign-up) is fully functional.

## Adding an archer

**From the mobile app (recommended):** open the app, tap "Add Archer" on the profile
picker, and fill in a name / archer ID / password. This calls `POST /api/archers`
(`mobile_app/backend/auth.py`), which generates a fresh `profile.json` from the schema
below, with identity/name filled in and everything else left `null`/`"TBD"` for the
archer or a coach to fill in later. Credentials go in a separate, gitignored
`archers/<id>/auth.json` — never in `profile.json`. New session JSONs uploaded through
the app are tagged with `archer_id` automatically once you're signed in as that archer.

**Manually (CLI-only workflows, or to hand-author a richer profile):**

1. Create `archers/<new_id>/` directory
2. Write `archers/<new_id>/profile.json` (see `mobile_app/backend/auth.py`'s
   `create_archer()` for the schema, or copy an existing profile as a template)
3. Optionally create `coaching_log.md`, `tournament_observations.md`, `red_camp_notes.md`
   to mirror the structure above
4. New session JSONs should include `"archer_id": "<new_id>"` in their metadata
5. To use the mobile app with a manually-created profile, set its password from the
   profile picker (it'll offer "Set up password" since no `auth.json` exists yet) — or
   call `POST /api/archers/<new_id>/set-password` directly
6. The detector, YOLO model, camera-invariance logic, and analysis tools all work
   without modification — they're archer-general

## What's archer-specific vs project-general

**Archer-specific** (lives in `archers/<id>/`):
- Identity, anthropometrics, equipment specs
- Coaches and coaching log
- Tournament observations and camp notes
- Baseline profile (once `tools/calibrate_archer.py` has enough sessions)
- Study setup parameters (location, distance, target face size)
- Audio capture choice (which device gets the lavalier, if used)
- Feedback latency preferences
- Active coaching focus / homework

**Project-general** (lives in `tools/`, `models/`, `ml_shot_detector/`):
- Detector code, YOLO model, pose adapter
- Camera-invariance methodology
- Audio-visual shot detector design
- The session JSON schema definition

## Coach confidentiality

Two independent mechanisms exist for archers who share a deployment with others but
want a coach's notes kept private from the app's display — see "Coach confidentiality
in the app" in `docs/WORKFLOW.md` for the full mechanism (hiding a coach's advice
entirely, or just redacting their name from generated feedback while keeping the
advice). Neither mechanism edits or deletes the underlying files.

## Privacy / multi-archer ethics

The platform code is archer-agnostic, but the deployment choices (where you record,
what you store, who else might appear in frame, whether you need consent/IRB approval
for a study) are yours to make for your own setup.
